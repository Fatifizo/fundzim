# Stage 3 Known Issues

Status of each item: **OPEN** (must be handled in the named stage), **ACCEPTED** (deliberate, with a reason) or
**ENVIRONMENT** (a property of the current developer machine, not of the code).

| ID | Issue | Impact | Status / owner stage |
|---|---|---|---|
| KI-01 | **No worker binary, River job queue, outbox dispatcher or idempotency middleware yet.** The `queue` schema and the `app.outbox_events` / `app.inbox_events` / `app.idempotency_keys` tables exist, but nothing writes or processes them. | Nothing asynchronous can run. No feature needs it in Stage 3. | OPEN — first items of Stage 4 ([STAGE-3-TO-STAGE-4.md](../stage-handover/STAGE-3-TO-STAGE-4.md)). |
| KI-02 | **Race detector not run locally.** `go test -race` needs cgo and a C compiler, and this machine has none. | Data races would be caught only in CI (which always runs `-race`). | ENVIRONMENT — install `gcc`, or rely on CI. |
| KI-03 | **`npm audit` reports 5 high-severity advisories in development tooling only** (`eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces`). `npm audit --omit=dev` reports 0. | No production exposure (lint tooling never ships). CI blocks on production dependencies and prints a warning for the dev-only chain; the finding is not hidden. | OPEN — re-check on every `eslint-config-next` release; remove the warning step once fixed upstream. |
| KI-04 | **The web proxy replaces the client's `X-Forwarded-For`**, so through the web container the API sees the container as the client. The per-IP rate limit then applies to the web container as a whole. | Local and staging rate limiting via the web origin is coarse. In production the reverse proxy routes `/api/v1` straight to the API and supplies the client IP (ARCHITECTURE §3). | OPEN — Stage 18 (production topology); the web proxy is a development/self-hosting convenience. |
| KI-05 | **The rate limiter is in-memory and per replica.** No Redis-backed limiter exists yet. | With N API replicas the effective limit is N× the configured one. | OPEN — Stage 4 (auth endpoints need per-account and per-route limits, SECURITY §10). |
| KI-06 | **The CSP allows `'unsafe-inline'` scripts in the web app.** Nonce-based CSP is not compatible with `cacheComponents`/partial prerendering in this Next.js version. No `unsafe-eval`, no third-party origins. | XSS hardening is weaker than FRONTEND.md §8 asks. | OPEN — revisit before Stage 7 (public campaign pages with user content). |
| KI-07 | **Integration tests write synthetic rows into the local development database** (audit events and outbox rows marked `platform.integration_test*`). Audit events are append-only and cannot be deleted. | Development databases accumulate test audit rows. CI uses a throwaway database. | ACCEPTED — reset local data with `make reset` (destructive) when needed. |
| KI-08 | **Middleware order differs from ARCHITECTURE §5:** the access log wraps panic recovery (§5 lists recovery before the access log). | None negative: the access log records the 500 a recovered panic produces, which the documented order would miss. | ACCEPTED — ARCHITECTURE §5 to be amended in Stage 4 with the auth middleware. |
| KI-09 | **SQL drafts and migrations were validated on PostgreSQL 18 (PGlite)** where Docker was unavailable; local and CI targets are PostgreSQL 17.11. | Version differences are possible. | See [testing.md](testing.md) for which checks ran on real PostgreSQL 17. |
| KI-10 | **Object storage is Garage, not MinIO.** MinIO's community container images are no longer published on Docker Hub. Garage supports per-bucket (not per-prefix) key grants, hence three buckets (design-baseline I-26). | Local behaviour differs from cloud S3 only in admin tooling. Production object storage is chosen in Stage 18. | ACCEPTED. |
| KI-11 | **`fundzimctl config check` prints only "configuration OK"**, not a redacted dump of the effective configuration. | Less helpful diagnostics. | OPEN — Stage 4 (low priority). |
| KI-12 | **No OpenTelemetry trace export and no Grafana/Prometheus deployment.** Request/correlation IDs, structured logs and Prometheus metrics (internal listener) exist. | Distributed tracing is not available yet. | OPEN — integration points documented in [observability](../architecture/observability.md); implement with the worker (Stage 4). |
| KI-13 | **No architecture tests yet** (import-graph and SQL-ownership tests from dependency-rules.md), and no golangci-lint. CI runs gofmt, `go vet` and govulncheck. | Module-boundary rules are not yet enforced mechanically (only the `platform` and `app` packages exist). | OPEN — Stage 4, before the first domain module (`users`/`auth`) is added. |
| KI-14 | **OpenAPI type generation for the web client is not set up.** | Types for Stage 3's three endpoints are hand-written and tested. | OPEN — when the first feature endpoints exist (Stage 4). |
| KI-15 | **Stage 1, Stage 2 and Stage 3 acceptance are not recorded.** | Process gap (CLAUDE.md stage discipline). | OPEN — project owner. |
